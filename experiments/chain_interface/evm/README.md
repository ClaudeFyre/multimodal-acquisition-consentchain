# B1 model-evidence registry experiment

This addition registers the supplied project's two frozen aggregate B1 conclusions through `BlockchainLedger`. The six-file B1 evidence commitment is preserved. Model training and patient-level prediction are not rerun. Name and description are configurable display metadata in `config/metadata.json`.

See `docs/中文说明.md` for measured results and author tasks, `docs/TERMINOLOGY.md` for digest definitions, and `docs/claim_evidence_map.json` for claim provenance. `results/sepolia_deployment.json` reports the public-network status; only `confirmed_on_sepolia` represents a completed successful demonstration.

## Reproduce the measured local workflow

Requirements: Node/npm, Python 3, Foundry/Anvil, Solidity 0.8.34 and the supplied aggregate result files. The recorded run used ethers 6.17.0 and Foundry 1.7.1. The frozen registry protocol is `config/protocol.json`, checked against `results/protocol_sha256.txt`.

```sh
npm ci --ignore-scripts --no-audit --no-fund
python3 scripts/prepare_evidence.py
forge test --use solc --json > results/forge_tests.json
python3 scripts/test_native_adapter.py
node scripts/benchmark.mjs
node scripts/audit_artifact.mjs
node scripts/audit_replay.mjs
python3 scripts/write_report.py
```

The benchmark starts and stops its own local Anvil instance on port 18545. The native adapter test uses 18546. Rerunning measurements replaces recorded local benchmark outputs; retain a copy if the previous measurements are needed. The source protocol was frozen before the recorded run. Changes to it require a new version and measurement rather than editing the saved commitment.

The paper is built from `papers/b1_jbhi/main.tex` in the repository root. `write_report.py` changes only the scoped governance passages and includes measured methods/results from JSON. It uses `source/main_before_blockchain.tex` as its preserved original. The clinical model values remain as supplied. `make_architecture.py` exports the updated diagram; the other original figures are retained.

## Sepolia and later label updates

`scripts/sepolia.mjs` is restricted to chain ID 11155111. It uses an encrypted local wallet directory given by `MODEL_REGISTRY_SECRET_DIR`, containing `sepolia-keystore.json` and `keystore-password.txt`. The wallet and password stay outside deliverables. A new account can be generated by the prepare command if the selected directory has no keystore. Use the funded deployment account for this existing contract.

```sh
# Set MODEL_REGISTRY_SECRET_DIR to the local encrypted wallet directory first.
npm run sepolia:status
npm run sepolia:deploy
```

For final author labels, change only the two `dataName`/`description` pairs in `config/metadata.json`, then run:

```sh
npm run metadata:update
python3 scripts/write_report.py
```

An unchanged label pair sends no transaction. Each changed pair produces a new metadata version and event. There is no function for modifying registered evidence or conclusions. New scientific content requires a new record ID/version.

To reuse or verify the original B1 adapter against the deployment:

```sh
# Run from the repository root with the same wallet environment.
python3 experiments/b1_cost_acquisition/anchor_results.py --backend evm
```

The adapter reads the deployment state by default. Identical registered content reuses the existing receipt. It reconstructs aggregate fields from on-chain storage and verifies the native off-chain files. It rejects unsupported A2 events.

To refresh the paper's successful-transaction table from the existing transactions, without a signer or new writes:

```sh
node scripts/export_sepolia_metrics.mjs
python3 scripts/write_report.py
```

The exporter verifies four successful receipts and their canonical block headers, then writes `results/sepolia_transaction_metrics.json`, its CSV equivalent, and `results/sepolia_metrics_rpc_snapshot.json`. Table VII in the paper includes gas used, actual fees, submission start, block time and the original client receipt latency. Its totals cover those four successful operations. Wall-clock times in the table are UTC; the metrics files also include UTC+8. Refreshing RPC evidence preserves the original client timing measurements.

## Interpretation

The controlled workload measures gas and client completion overhead. The signed centralized log has lower measured overhead, with different trust and durability semantics. A valid truncated signed log needs a trusted head checkpoint for completeness verification. Anvil tests do not evaluate consensus security. A public successful receipt establishes observed inclusion. Evidence URIs reference files in this private project; public registration does not provide file hosting or grant repository access.

The original repository's rights and redistribution restrictions continue to apply. This local delivery does not authorize public source publication.
